# Spec-Driven Development

A spec is a contract the AI can read and a human can review. Sections include:

problem · goals · non-goals · users · use cases · functional reqs · NFRs · data model · API contracts · risks · acceptance criteria (Given/When/Then) · rollout.

Each spec is auto-numbered (`0001-…`, `0002-…`) and stored in `docs/specs/`.
