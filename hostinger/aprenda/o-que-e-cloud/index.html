O que é Cloud Computing?

⏱ 8 min de leitura·+30 XP

Antes de falar de EC2, S3, Lambda ou qualquer outro serviço, você precisa entender por que a nuvem existe. Cloud Computing não é "colocar servidor na internet" — é um modelo econômico e operacional que muda como empresas lidam com TI. O exame CLF-C02 começa por aqui, e com razão: sem esse alicerce, os outros domínios não fazem sentido.

Onde isso entra no exame

📘 Domain 1 — Cloud Concepts· 24%

O domínio 1 do CLF-C02 cobre: definição de nuvem, benefícios, modelos (IaaS/PaaS/SaaS), modelos de deployment (pública/privada/híbrida) e os 6 pilares do Well-Architected. Esse artigo cobre as 3 primeiras áreas — os pilares vêm em um artigo dedicado mais à frente.

A definição oficial (NIST)

O NIST (National Institute of Standards and Technology) define cloud computing como um modelo que permite acesso sob demanda, via rede, a um pool compartilhado de recursos de computação configuráveis (servidores, storage, networking, aplicações) que podem ser provisionados e liberados rapidamente com mínimo esforço de gerenciamento.

Na prática, isso significa 5 características essenciais. A AWS usa exatamente essa base conceitual:

🧠 Cloud Computing — 5 características essenciais (NIST)

On-demand self-service

  • →Usuário provisiona recursos sem intervenção humana do fornecedor
  • →Ex.: lançar uma EC2 em 30s pelo console

Broad network access

  • →Recursos acessíveis via rede padrão (HTTP/HTTPS)
  • →Desktop, mobile, IoT — qualquer cliente com TCP/IP

Resource pooling

  • →Multi-tenancy: muitos clientes compartilhando o mesmo hardware físico
  • →Recursos alocados dinamicamente conforme demanda

Rapid elasticity

  • →Escala para cima e para baixo automaticamente
  • →Do ponto de vista do cliente, recursos "parecem" ilimitados

Measured service

  • →Uso monitorado, controlado e reportado
  • →Cobrança granular (pay-as-you-go)

Os 6 benefícios da nuvem (AWS oficial)

A AWS documenta 6 vantagens principais. Saber essas 6 de cor é regra para o CLF-C02 — aparecem literalmente transcritas em questões:

1

Trade CapEx for variable expense

Em vez de investir milhões em data centers que podem ficar ociosos, você paga apenas pelo que usar — hora de EC2, GB transferido, requisição feita.

2

Benefit from massive economies of scale

A AWS compra hardware em escala global. Esse desconto de volume é repassado para o cliente — por isso os preços caem ano após ano (já houve mais de 100 reduções desde 2006).

3

Stop guessing capacity

Sem nuvem, você compra servidores antecipando pico de demanda (caro e ocioso) ou subdimensiona (fica fora no Black Friday). Com nuvem, Auto Scaling ajusta a capacidade em tempo real.

4

Increase speed and agility

Um ambiente de testes que antes demorava semanas para ser provisionado agora sobe em minutos. Time-to-market de features despenca.

5

Stop spending money running and maintaining data centers

Geração, refrigeração, rede, segurança física, substituição de discos — tudo isso deixa de ser problema seu. Seu time foca em produto, não em infra.

6

Go global in minutes

Com um clique você sobe uma aplicação em Regiões em São Paulo, Tóquio, Frankfurt e Ohio simultaneamente. Isso seria inviável com data centers físicos.

Modelos de serviço: IaaS, PaaS, SaaS

Os 3 modelos diferenciam-se por quanto da pilha o cliente gerencia. Quanto mais alto no stack, menos responsabilidade do cliente.

Regra de ouro do exame: se a questão fala "você instala o SO e aplica patches" → IaaS. Se fala "plataforma gerenciada onde você só faz deploy do código" → PaaS. Se fala "aplicação pronta acessada via web" → SaaS.

Modelos de deployment

Onde a infraestrutura de nuvem roda fisicamente? Três opções:

ModeloOnde rodaUso típico
Pública (Cloud)Data centers da AWS, Azure, GCPStartups, web apps modernas, analytics
Privada (On-premises)Data center da própria empresaBancos legados, órgãos militares, compliance estrito
HíbridaCombinação on-prem + públicaMigração gradual, compliance parcial, burst para cloud

A AWS oferece serviços específicos para cada modelo híbrido:

  • • AWS Outposts — racks AWS dentro do seu data center
  • • AWS Direct Connect — link dedicado (fibra) entre on-prem e VPC
  • • AWS Storage Gateway — cache local com replicação para S3
  • • AWS Snow Family (Snowcone/Snowball/Snowmobile) — migração física de petabytes
  • • VMware Cloud on AWS — estende clusters VMware para a nuvem

Cenários reais: qual modelo escolher

📋 Startup fintech precisa lançar MVP em 3 semanas

✓ Cloud pública pura (AWS)

Velocidade > tudo. Sem CapEx, provisiona em minutos, ajusta capacidade no voo, paga só pelo que usa. CapEx zero preserva runway.

Alt: Cloud híbrida — Exagero para MVP; burocracia sem benefício

📋 Banco com sistema mainframe COBOL que roda há 30 anos

✓ Cloud híbrida

Migrar mainframe puro é arriscado e caro. Mantém-se o core on-prem via Direct Connect e move-se o que faz sentido (analytics, web front, mobile backend) para AWS.

Alt: On-prem — Fica para trás em inovação e custo

Alt: Cloud pura — Big-bang migration é risco desnecessário

📋 Órgão militar com dados classificados de defesa nacional

✓ Cloud privada (ou AWS GovCloud)

Regulação pode exigir que os dados não deixem território soberano com garantias específicas. AWS GovCloud é uma região isolada da AWS para esse fim.

Exemplos práticos: o que cada modelo parece

exemplo — IaaS (EC2)
# Você recebe: servidor virtual vazio
# Você instala: Ubuntu, Nginx, sua app, patches, firewall
aws ec2 run-instances \
  --image-id ami-0c55b159cbfafe1f0 \
  --instance-type t3.micro \
  --key-name minha-chave
exemplo — PaaS (Elastic Beanstalk)
# Você entrega: código da aplicação
# AWS gerencia: SO, runtime, load balancer, auto-scaling, patches
eb init -p python-3.11 minha-app
eb create meu-ambiente
eb deploy
exemplo — SaaS (Chime)
# Você só usa. Não há provisionamento.
# Abre o navegador em https://app.chime.aws → login → reunião.
⚠️
Armadilha frequente: "DynamoDB é IaaS?" — Não. DynamoDB é totalmente gerenciado (você não gerencia SO, storage, réplicas). Tecnicamente é considerado PaaS ou "managed service". O exame pode chamar de "managed database service" — fique atento à terminologia.

Perguntas típicas do exame (Q&A)

❓ Qual característica descreve a elasticidade da nuvem?

A capacidade de provisionar e liberar recursos automaticamente conforme a demanda, para cima e para baixo. Diferente de scalability (capacidade de crescer), elasticidade enfatiza o ajuste dinâmico — inclui reduzir recursos quando a demanda cai.

❓ Um cliente quer reduzir o custo de TI mantendo controle total sobre o hardware. Qual modelo?

Cloud privada on-premises. Ele mantém controle total, mas continua com CapEx alto. Se ele também quer reduzir CapEx, considere cloud híbrida.

❓ Qual serviço AWS representa o benefício 'go global in minutes'?

Qualquer serviço com distribuição global: CloudFront (CDN), Route 53 (DNS global), ou simplesmente lançar uma aplicação em múltiplas Regiões. O ponto é que isso leva minutos, não meses.

❓ Diferença entre 'scalability' e 'elasticity' para o exame?

Scalability = capacidade de crescer (pode ser manual). Elasticity = ajuste automático e bidirecional (cresce e encolhe). O CLF-C02 cobra essa distinção em múltiplas questões.
✅
Take-aways:Cloud é um modelo econômico (OpEx > CapEx) + operacional (elástico, sob demanda, medido). IaaS/PaaS/SaaS diferem pelo nível de gerenciamento do cliente. Deployment pode ser público, privado ou híbrido. A AWS defende 6 benefícios oficiais — decore-os literalmente. Esse é o alicerce dos outros 3 domínios.
