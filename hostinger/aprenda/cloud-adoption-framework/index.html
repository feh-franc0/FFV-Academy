Cloud Adoption Framework e os 7 Rs da Migração

⏱ 9 min de leitura·+45 XP

Migrar para a nuvem é mais que copiar servidores — envolve pessoas, processos e tecnologia. O AWS Cloud Adoption Framework (CAF) estrutura essa jornada em 6 perspectivas, e as 7 estratégias de migração (7 Rs) definem como cada workload deve ser tratada. O CLF-C02 cobra ambos em questões de cenário.

Onde isso entra no exame

📘 Domain 1 — Cloud Concepts· 24%

CAF e 7 Rs aparecem em questões de estratégia. A banca testa se você reconhece: (1) as 6 perspectivas do CAF e seus focos; (2) cada uma das 7 estratégias de migração e quando aplicar. Não exige configurar tools, mas exige identificar o R certo para um cenário descrito.

AWS Cloud Adoption Framework (CAF) — 6 perspectivas

🧠 AWS CAF — 6 Perspectivas

1. Business

  • →Garantir que investimentos em cloud acelerem outcomes de negócio
  • →Capacidades: strategy management, portfolio management, innovation, data monetization

2. People

  • →Cultura, treinamento, liderança, organização
  • →Capacidades: culture evolution, transformational leadership, cloud fluency, workforce transformation

3. Governance

  • →Gerenciar, medir e melhorar iniciativas cloud
  • →Capacidades: program / project management, risk management, data governance, people analytics

4. Platform

  • →Criar plataforma escalável e provisionada por código
  • →Capacidades: platform architecture, data architecture, CI/CD, IaC

5. Security

  • →Proteger confidencialidade, integridade e disponibilidade
  • →Capacidades: identity & access, threat detection, vulnerability, compliance, incident response

6. Operations

  • →Entregar serviços cloud alinhados com expectativas do negócio
  • →Capacidades: observability, event management, incident & problem, change & release
💡
Mnemônica: "Business People Govern Platforms with Security and Operations". Perspectives = áreas organizacionais impactadas pela adoção.

AWS Migration Evaluator (antes TSO Logic)

Ferramenta gratuita da AWS que analisa a infra on-prem (via um coletor rodando no ambiente) e gera um business case de migração: TCO atual vs AWS, recomendação de instâncias, ROI. Usada nas fases iniciais da jornada descrita pelo CAF.

AWS Migration Hub

Hub central que rastreia o progresso de migração de workloads por múltiplas ferramentas AWS e parceiras. Integra com:

  • • AWS Application Migration Service (MGN) — replica servidores para AWS (lift-and-shift)
  • • AWS Database Migration Service (DMS) — migra bancos homogêneos e heterogêneos
  • • AWS Schema Conversion Tool (SCT) — converte schemas e stored procedures
  • • AWS DataSync — migra dados em larga escala via rede
  • • AWS Snow Family — migração física offline

As 7 estratégias de migração (7 Rs)

Também conhecidas como as "7 Rs da migração". Originalmente eram 5 (Gartner), depois 6, agora 7. Decore cada uma:

EstratégiaDescriçãoExemplo
1. Rehost ("lift-and-shift")Mover sem mudanças. Rápido, barato inicialmente.VM VMware on-prem → EC2 equivalente via MGN
2. Replatform ("lift-tinker-and-shift")Pequenas otimizações para aproveitar AWS.Trocar MySQL on-prem por Aurora MySQL (mesma interface)
3. Refactor / Re-architectReescrever a aplicação para cloud-native.Monólito → microservices em ECS + Lambda + DynamoDB
4. Repurchase ("drop-and-shop")Abandonar e adotar produto SaaS.Sair do Siebel CRM on-prem para Salesforce
5. RetireDescomissionar. A app não é mais necessária.App interno usado por 3 pessoas que já usam outra ferramenta
6. Retain ("revisit later")Manter on-prem por enquanto (mainframe, compliance).Sistema COBOL crítico ainda não migrado
7. RelocateMover sem mudanças para VMware Cloud on AWS.Cluster VMware → VMware Cloud on AWS (mesmo hypervisor)

Cenários de decisão

📋 ERP monolítico Oracle on-prem, a empresa precisa migrar em 4 meses por fim do contrato do DC

✓ Rehost (MGN) + backlog de Replatform

Tempo é crítico — Rehost via MGN replica servidores para EC2 em semanas. Após migração, modernize incrementalmente (Oracle → Aurora, batch → Lambda).

📋 App legada Windows .NET Framework 4.5 que está virando problema

✓ Refactor gradual — Strangler Pattern

Reescreva pedaços em .NET moderno (ou outra stack) atrás de um API Gateway, desativando funcionalidades legacy progressivamente. Reduz risco vs big-bang.

📋 Sistema de RH on-prem com licenças ExpensePaolo a vencer

✓ Repurchase — adotar Workday ou similar

Por que rodar HRIS próprio quando existe SaaS maduro? Elimina manutenção, updates, backup, DR. Custo previsível por usuário.

📋 Cluster VMware de 300 VMs — empresa quer mover rapidamente sem mudanças

✓ Relocate para VMware Cloud on AWS

Mesmo vCenter, mesmos tools, mesmas VMs. Migração em horas via vMotion. Ideal para sair do DC físico sem refactor. Posteriormente, Rehost/Replatform individualmente.

Six advantages of cloud — revisão

Ao planejar migração, a AWS reforça os 6 benefícios (já vistos em "O que é Cloud Computing") como driver de ROI:

  1. Trade CapEx for variable expense
  2. Benefit from massive economies of scale
  3. Stop guessing capacity
  4. Increase speed and agility
  5. Stop spending money running data centers
  6. Go global in minutes
⚠️
Pegadinha clássica: "Rehost" é o mesmo que "Lift-and-shift". "Replatform" é "Lift-tinker-and-shift". "Refactor" é "Re-architect". Questões podem usar qualquer variante dos nomes.

Perguntas típicas (Q&A)

❓ Qual ferramenta AWS ajuda a construir um business case para migração?

AWS Migration Evaluator (antes chamado TSO Logic). Analisa a infra on-prem e gera TCO comparado à AWS.

❓ Diferença entre Refactor e Replatform?

Refactor = reescrever a arquitetura (monólito → microservices). Replatform = pequenos ajustes para aproveitar AWS (trocar Oracle por Aurora, mas manter estrutura do app).

❓ Qual perspectiva do CAF trata de 'treinamento e cultura'?

People. Aborda cloud fluency, transformational leadership, workforce transformation, organizational design.

❓ Uma empresa VMware quer migrar rapidamente mantendo todo o ambiente VMware. Estratégia?

Relocate — usa VMware Cloud on AWS para mover sem mudanças no hypervisor, mantendo vCenter/vSphere.
✅
Take-aways: CAF = 6 perspectivas (Business, People, Governance, Platform, Security, Operations) — roteiro organizacional. 7 Rs = 7 estratégias (Rehost, Replatform, Refactor, Repurchase, Retire, Retain, Relocate) — decisão por workload. Rehost = mais rápido, menos benefícios. Refactor = mais lento, mais benefícios cloud-native. Migration Evaluator = TCO; Migration Hub = orchestration; MGN = replicação server-level; DMS = bancos.
